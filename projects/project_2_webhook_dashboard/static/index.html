Webhook → Live Dashboard

External services POST signed events to /webhook/payment. The backend verifies the HMAC, dedups by event id, stores in SQLite, then pushes live to dashboards via SSE. Two dashboards below show the same data the polling way and the SSE way.

Simulate webhook traffic:

POLLING   Dashboard A (the old way)

Calls GET /events?since=N every 2 seconds. Note the polls that return empty arrays - the cost of "checking just in case."

SSE   Dashboard B (live push)

Opens one GET /stream connection. Server pushes events as they arrive. Zero traffic when idle.

What to watch:
  1. Idle period: open DevTools Network. Polling fires every 2s even with no events. SSE shows ONE connection sitting open.
  2. Fire a burst: SSE updates instantly. Polling updates on its next tick (up to 2s late).
  3. Dedup: click "Send duplicate" - server returns {duplicate:true} and no extra row appears.
  4. Forgery: click "Send unsigned" - server returns 401, nothing is stored.
Backend: server.py. Endpoints: POST /webhook/payment, GET /events?since=N, GET /stream.

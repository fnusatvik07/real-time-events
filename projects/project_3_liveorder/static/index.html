LiveOrder - all 4 real-time patterns in one app

A mini food-delivery app. Place an order, simulate Stripe paying for it, watch it auto-progress to delivery, chat with the driver, ask the AI recommender what to order next, generate a revenue report. Each pattern below is labeled with which real-time approach delivers it.
SSE WebSocket Webhook Polling SSE (LLM token stream)

Order SSE

Server pushes status changes (and webhooks received, and chat messages) to this card over one SSE connection per order.

no order yet - SSE: idle
Place an order to see live updates here.

Payment WEBHOOK

Simulates Stripe POSTing a signed payment_intent.succeeded event to our /webhooks/payment. HMAC verified, then dispatched to the order's state machine.

The HMAC-signed webhook arrives, signature is verified, then this triggers the order's auto-advance through paid -> cooking -> out for delivery -> delivered.
No webhooks received yet.

Driver chat WebSocket

Bidirectional chat tied to the order. Open this page in two windows (one as customer, one as driver) to see live two-way messages over a single TCP connection.

disconnected
Connect after placing an order.

Food recommender SSE / LLM

Streams a real OpenAI gpt-4o-mini response over SSE - backend relays each token to the browser as it's generated.

Ask a question to stream a response here.

Revenue report POLLING

Long-running background job. UI POSTs to kick it off, then polls GET /api/reports/{id} every second until status == done. This is the right pattern for slow batch work where push is overkill.
